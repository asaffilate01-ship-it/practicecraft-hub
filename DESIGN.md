# TaxLounge design system

## Brand direction
Professional, welcoming and information-dense rather than theatrical: a confident UK accountancy workspace built for long sessions, careful reviews and trust. Avoid copying another fintech brand.

### Existing tokens
- `src/index.css` is authoritative: chalk background `hsl(80 13% 96%)`, deep evergreen foreground `hsl(164 19% 11%)`, restrained olive accents, semantic red/amber/green status tones.
- Keep legible body and heading typography, clear hierarchy, regular gutters, consistent tabular numerals for money, restrained transitions and generous touch targets.
- Preserve practice-specific tenant logo/name/colours when supplied; otherwise the default product identity is **TaxLounge**.
- Brand identity is presentation only. Tenant, role, plan, RLS and central Factory binding must continue to be enforced by the real backends.

## Screens and interaction
- **Practice home:** lead with next work, risk/priority, owner, due date, recorded provider status, clear deep-link and evidence. Separate incomplete data and errors from successful zero states.
- **Client workspace:** show firm/client context persistently, searchable records, audit timeline and document requests without accidental cross-client navigation.
- **Accounts, payroll and returns:** display preparation state, approver, source, calculations, acknowledgements and whether the work is safe to file. Never make a colour alone communicate status.
- **AI Review Centre:** record provenance, model/provider, source record, validation results and a deliberate accept/reject action. No autogenerated approvals.
- **Marketing/auth:** no fabricated free trial, customer ratings, HMRC recognition, logos, contact addresses or domain claims. Auth pages are currently not the marketing site.
- **Mobile:** 360/390px flows, supported modules only, 44px-style tap targets, accessible sheets, safe-area bottom navigation and horizontal overflow handled deliberately.
- **Large screens:** 768px and 1440px, 200% browser zoom, flexible columns, sane table density, loading and long-label behavior.
- **Accessibility:** keyboard-only journeys, visible focus, semantic labels, 4.5:1 normal text contrast target, reduced-motion preference, readable error summaries and screen-reader status announcements.
- Use responsive editorial hierarchy and meaningful negative space; avoid nested-card overload, empty decorative gradients and skeletons without a recoverable state.

## How to apply the requested resources
- [Taste Skill](https://github.com/Leonxlnx/taste-skill): use audit-first redesign, visual hierarchy and restrained information density; keep routes and forms stable.
- [Impeccable](https://github.com/pbakaus/impeccable): use `critique`, `audit`, `harden`, `polish`, `adapt` and source detector; its GitHub Actions source scan is advisory, not a rendered-browser test.
- [Awesome DESIGN.md](https://github.com/VoltAgent/awesome-design-md): learn from documented tokens and patterns, never copy proprietary design, trademarks or unverifiable proof.
- The source audit is already wired to CI in this PR. Perform real browser/keyboard/screenshot QA separately and record exact device/viewports.

## Acceptance checklist
Run `npm run typecheck`, `npm test`, `npm run build`, `npm run lint:security` and dependency review; run authorised staff/portal/employee flows against staging; keep open PRs unmerged until release blockers and visuals are reviewed.
